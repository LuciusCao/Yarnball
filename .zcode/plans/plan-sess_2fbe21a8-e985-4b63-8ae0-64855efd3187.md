# Odessey — Agent-native 地图行程编辑器 · v1 实施方案

## 0. 产品定义

以地图为画布的旅行攻略产品：行程不是文档，而是地图上的节点（酒店/餐厅/景点/活动）+ 节点间的交通段，按天串联。用户在右侧 1/3 面板与**自己的 agent**（通过 ACP 接入，如 `kimi acp`）对话，agent 通过产品暴露的 MCP 工具直接读写行程数据结构，地图 2/3 区域实时刷新。核心体验：粘贴小红书攻略文本/携程酒店候选 → agent 解析、地理编码、编排到各天 → 地图上实时出现标记和路线 → 顺路度分析与重排建议。

**v1 范围**：Web（桌面优先）、国内目的地（高德）、单人编辑 + 只读分享链接、本地自托管单机、无用户体系。
**v1 不做**：实时协同编辑（CRDT）、出境游、图片粘贴解析、云部署多租户、移动端。

**验收 demo 脚本**：创建「杭州 3 日游」→ 粘贴一篇小红书西湖攻略文本 → agent 调 `search_poi` 解析坐标并建 POI、排入 Day 1，地图实时出点、连线 → 粘贴 3 家携程酒店候选 → agent 建酒店候选 → 问「灵隐寺放哪天最顺路」→ agent 调 `analyze_detour` 给出分析并重排 → 选定酒店，路线重算 → 生成只读分享链接。

## 1. 技术决策（已确认 + 默认项）

| 决策 | 选择 |
|---|---|
| 后端 | Node + **Hono**（`@hono/node-server`），TS 全栈 |
| 前端 | React 19 + Vite + TS + Tailwind CSS v4 + TanStack Query + Zustand |
| ACP | `@agentclientprotocol/sdk`（官方 TS SDK，Zed 参考实现），产品作为 ACP client |
| MCP | `@modelcontextprotocol/sdk`，`StreamableHTTPServerTransport` **stateless 模式**（每请求新 transport，天然支持 per-request header 鉴权重解析，规避 agent-legion 踩过的 session-manager lifespan 坑） |
| 地图 | **高德 JSAPI 2.0**（`@amap/amap-jsapi-loader`）渲染；Web 服务 API（POI 搜索/路径规划/距离）走服务端。地理服务统一收在 `GeoProvider` 接口后，v2 出境游加 provider |
| DB | PostgreSQL 16（docker compose）+ Drizzle ORM + drizzle-kit |
| 实时 | SSE（复用 agent-legion 验证过的模式） |
| Monorepo | pnpm workspaces：`apps/server`、`apps/web`、`packages/shared`（zod schema 单一定义点，供 Drizzle 校验、MCP 工具入参、前端类型三处共享） |

**前置条件**：注册高德开放平台（lbs.amap.com），创建两个 key——「Web 端(JS API)」和「Web 服务」。`.env.example` 列出，缺失时服务端相应接口返回明确错误、前端显示配置引导横幅。

## 2. 架构

```
┌─ Browser ──────────────────────────────────────────────┐
│  React App                                             │
│  [地图 2/3: AMap JSAPI]  [右 1/3: 对话/行程/酒店 tabs]  │
│      ▲ SSE(trip + chat 事件)      │ REST(人直接编辑)   │
└──────┼────────────────────────────┼────────────────────┘
       │                            ▼
┌──────┴─────────── Hono Server ────────────────────────┐
│  REST routes ──► TripService ──► Postgres (Drizzle)   │
│  SSE EventBus ◄────┘(所有变更：人 + agent 双写入口)    │
│  /mcp (streamable HTTP, stateless)                     │
│   ▲ Bearer scoped token + x-session header             │
│   │ session/new(mcpServers=[http spec]) 注入            │
│  AcpSessionManager ── spawn 子进程 ──► kimi acp 等     │
│   (stdio JSON-RPC: prompt/permission/terminal)         │
└────────────────────────────────────────────────────────┘
```

三层分离（与 agent-legion 同构）：ACP=对话面，MCP=工具面，SSE+REST=交互面。

## 3. 数据模型（Drizzle）

- `trips`: id, title, destination_city, city_adcode, start/end_date, selected_hotel_candidate_id, share_token(只读分享)
- `places`: id, trip_id, name, category(attraction|restaurant|hotel|activity|other), lng/lat, address, amap_poi_id, source_type(xiaohongshu|ctrip|manual|agent), source_url, notes, duration_min, price_cny, created_by(human|agent)
- `days`: id, trip_id, day_index, date
- `entries`: id, day_id, place_id, position, start_time?, note
- `transport_legs`: id, day_id, from/to_entry_id, mode(walk|taxi|transit|drive), distance_m, duration_s, polyline(JSON), computed_at —— 人或 agent 变更 entry 后自动重算该天的 legs
- `hotel_candidates`: id, trip_id, place_id, price_per_night, notes
- `chat_sessions`: id, trip_id, agent_id, status(idle|running|closed|error), ui_context(用户当前选中点/天，agent 经 get_trip_context 实时读)
- `chat_messages`: id, session_id, seq, kind(user_text|agent_text|agent_thought|tool_call|tool_call_update|plan|permission_request|permission_result|error), content(JSONB)
- `agent_registry`: id, label, command, args[], enabled —— 种子：kimi(`kimi acp`，主力)、claude-code-acp、自定义
- `agent_tokens`: session_id, token_hash(sha256，明文只在 session/new 出现一次), revoked_at

## 4. MCP 工具面（暴露给 agent 的操作）

- `get_trip_context()` —— 行程全貌 + 用户当前 UI 选中上下文（agent-legion get_studio_context 模式）
- `search_poi(keyword, city?)` —— 高德地点搜索 → 候选(名称/地址/坐标/poi_id)。**bootstrap prompt 强制：建 POI 前必须先 search_poi 拿真实坐标，禁止编造经纬度**
- `add_place` / `update_place` / `remove_place`
- `add_hotel_candidate` / `select_hotel`
- `add_place_to_day(place_id, day_index, position?)` / `move_entry` / `remove_entry`
- `suggest_day_order(day_index)` —— 距离矩阵 + 最近邻 + 2-opt，返回优化前后对比（不直接生效）
- `reorder_day(day_index, entry_ids[])` —— 直接生效（SSE 推送前端）
- `get_route(from, to, mode)` —— 高德路径规划
- `analyze_detour(place_id, day_index)` —— 顺路度：插入该天各位置的时间增量 + 最优位置推荐

## 5. ACP 层（移植 agent-legion 已验证模式 + 坑清单）

- 每 chat session 一个 agent 子进程（`AcpClient` + stdio transport）；initialize 时 `clientInfo: odessey`、capabilities 含 `terminal: true`
- `session/new(cwd=<per-session 临时目录>, mcpServers=[HttpMcpServer{url: /mcp, headers: [Authorization Bearer <scoped token>, x-odessey-session]})` —— **MCP 必须是 HTTP 端点**（kimi 只收 http/sse 类型）；resume 时若 agent 声明 loadSession 先试 `session/load`，失败降级 session/new + 压缩转录回放（6k 字符预算）
- prompt 循环：队列 + `session/prompt([TextContentBlock])`；cancel 经 SDK 打断飞行中的 turn；1h 兜底超时
- session/update 分流：`agent_message_chunk`/`agent_thought_chunk` 每 turn 聚合（**聚合槽在 turn 开始时 reset**——trailing chunks 坑）、`tool_call/update` 落库并渲染可展开卡片、plan 落库
- **terminal 协议必须实现**（terminal/create、output、wait_for_exit、release、kill 五方法 + 独立进程组），否则 kimi 的 Bash/Grep 全挂
- permission 四层策略：① Odessey MCP 工具自动批准（只信结构化身份字段 title/kind/name，**绝不序列化 payload 做匹配**——防伪装）② 只读 kind(read/search) 自动批准 ③ session 级 allow-all 开关 ④ 停靠 UI 等人答，120s 超时自动 deny
- 生命周期：close = 排空队列 → SIGTERM → 5s → SIGKILL（kill 前重校验 pid 身份）；stderr 持续排水防死锁；并发 session 上限 32
- 每 session 首个 prompt 前注入 bootstrap 文案（角色、工具边界、search_poi 纪律、草稿建议流程）；MCP 可见性冒烟：session 从未出现本产品工具调用 → turn 结束后一次性 advisory 提示
- Node 单线程事件循环天然消除 agent-legion 最痛的线程桥接类 bug（daemon 线程、call_soon_threadsafe、anyio 池死锁、loop wedge kill 不到进程）

## 6. 前端

- 布局：左 2/3 地图，右 1/3 tabs（**对话**默认 / 行程 / 酒店）
- 地图：POI 标记按天配色 + 天内序号；酒店候选特殊图标、选定酒店高亮；每天路线 polyline（真实路径几何）；Day 筛选 chips；点击标记 → 弹出信息卡 + 联动行程 tab
- 行程 tab：按天分组的时间轴，entry 间显示交通段（「步行 12 分钟 · 850 米」），拖拽/上下移重排，手动搜索添加地点（人直接编辑路径，与 agent 并行）
- 酒店 tab：候选卡（价格/晚、来源链接、备注），选择按钮；地图上叠加「推荐住宿区域」（各天 POI 质心的中位数圆圈）
- 对话 tab：流式消息（**流式中纯文本渲染，turn 完成后才渲染 markdown**——半截 markdown 抖动坑）、tool_call 可展开卡片、permission 待答卡（允许/拒绝/allow-all）、agent 选择器（registry）、发送队列
- SSE：trip 频道（数据变更 → upsert）+ chat 频道（消息 upsert、session 状态）；断线重连 + turn_end 全量回取自愈；用户选中态回写 session.ui_context
- 只读分享：`/share/:token` 渲染地图+行程，无编辑无对话

## 7. 顺路核心算法

- legs 重算：entry 增删移/选酒店 → 重算受影响天的连续点对，默认模式（<2km 步行，否则驾车），高德 direction API，结果缓存
- `analyze_detour`：枚举插入位置算全链路时长增量
- `suggest_day_order`：高德距离矩阵 API（批量），最近邻初始解 + 2-opt 迭代，输出前后对比

## 8. 安全（本地 v1）

无用户体系、CORS 锁本地。沿用 agent-legion 模式：per-session scoped token（绑 trip，明文只在 session/new 出现，库存 sha256，关 session 即吊销）；MCP 端点中间件校验 token + session 绑定；agent 命令行不暴露给前端 API。

## 11. 里程碑

- **M1 地图骨架**：monorepo 脚手架、DB+迁移、Hono、React 壳 + AMap 加载、行程 CRUD、手动添加地点 + 标记渲染
- **M2 ACP+MCP 跑通（魔法时刻）**：MCP server + 全部基础工具、ACP session 管理（spawn/initialize/new/prompt/update/permission/terminal）、对话 UI 流式、fake agent 测试、kimi 真机联调——粘贴小红书文本 → 地图实时出点
- **M3 行程串联**：entries 排序 + 拖拽、交通段计算 + polyline、时间轴 UI、suggest_day_order / analyze_detour / 酒店候选 / 推荐区域 / 只读分享
- **M4 打磨**：resume、cancel 健壮性、MCP 提示、permission 卡片、错误态、README（高德 key 配置 + kimi 注意事项）

各里程碑完成后可运行验证。git init + 初始提交随 M1 一起做。

## 12. 主要风险与对策

- **ACP TS SDK API 细节**（AcpClient/transport 具体签名）：实施开始时先读 SDK 文档/examples 对齐，fake agent 基于真实协议消息构建，不依赖 SDK 内部
- **kimi 版本行为差异**：所有 agent-legion 记录的 kimi 坑（http-only MCP、terminal 协议、session/load 可能失败）已纳入设计
- **agent 编造坐标**：bootstrap prompt 纪律 + add_place 校验坐标在该城市 adcode 附近，越界拒绝并提示先 search_poi
- **高德配额**：个人免费额度足够 v1；GeoProvider 接口留缓存层
